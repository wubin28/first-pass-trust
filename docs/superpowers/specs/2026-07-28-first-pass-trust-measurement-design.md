# 设计：可信度度量体系与第一章改稿（五闸门 + 单臂解剖 + 第六章对照实验）

- 日期：2026-07-28
- 范围：新增 `ch01/README.md` 的 1.2 与 1.3 两节（原 1.2–1.6 顺延为 1.4–1.8）；新增 `ch06` 的对照实验一节；扩写 `ch03/README.md` 的 3.8 节
- 目标：为全书唯一问题——"如何让 AI 在有限 token 预算下第一次就生成可信的代码"——提供一套可判定、可复现、成本自洽的度量体系，并用它重构开篇的阅读体验

## 1. 背景与动机

书稿目前把"可信"当作一个形容词使用。1.2 节说"把信任从主观判断变成可验证的工程流程"，3.7 节用需求—证据矩阵、3.8 节用故障注入——这些零件都在，但**没有一个统一的、可判定的"可信"定义**，也没有任何数据能支持"用了这套方法比不用更可信"这一全书隐含承诺。

同时开篇存在阅读体验问题：ch01 通篇是方法论概述，读者在读到 ch03 的真实踩坑之前，没有任何"痛"的实感。

本设计一次解决两件事：定义可信、并用这个定义重构开篇。

## 2. 已确定的决策

| # | 决策点 | 结论 |
| --- | --- | --- |
| D1 | 度量体系的定位 | **书里用来证明方法论有效的证据**，不是交付读者在自己项目上跑的工具 |
| D2 | A 臂（对照组）的公平性标准 | 允许**一段写得相当不错的自然语言需求**；不允许 EARS、决策表、验收标准、TDD skill、code review skill、故障注入 |
| D3 | 开篇是否放双臂对照实验 | **不放。** ch01 只放单臂（A 臂）失败解剖；双臂实验放第六章 |
| D4 | 第六章双臂实验的形态 | 3 个需求 × 每臂重复 3 次（重复测量），主报**方差**而非均值 |
| D5 | SMS（规格变异分数） | 作为本书原创概念正式提出，中文定名**「规格变异分数」** |

D3 的理由（brainstorming 结论）：开篇需要的是**演示**而非**证明**。证明需要读者已有概念储备（EARS、决策表、需求—证据矩阵四档），而 ch01 时读者储备为零；且 n=1 撑不住"B 优于 A"这种比较性论断，在开篇放弱证据会损伤全书信用锚。单臂失败解剖是**存在性证明**，n=1 完全成立。

## 3. 核心定义：五闸门

一次生成的代码称为**可信的**，当且仅当在**零人工语义纠正**的前提下，它连续通过下列五道闸门：

| 闸门 | 判据 | 检测手段 | 类型 |
| --- | --- | --- | --- |
| G1 编译/构建 | 目标模块在无特殊参数下构建成功 | `mvn test` 退出码 | computational |
| G2 回归绿 | 全量既有测试套件不变红 | 与基线 test 数、failures、errors 对比 | computational |
| G3 规格覆盖 | 需求的每条规则与验收标准都有**自动化直接覆盖** | 需求—证据矩阵四档判定 | inferential |
| G4 变异敏感 | 针对每条规则的最小语义变异能被现有测试杀死 | 故障注入 / mutation testing | computational |
| G5 范围守卫 | 未新增需求明确排除的公开 API 或行为 | diff 对照"明确不做"清单 | computational |

两条配套约定，必须原样写进书里：

- **单调收紧**：五道闸门按严格程度递增。评分取**连续通过数**，遇到第一个不通过即停——G3 没过时测 G4 无意义（一条压根没测的规则谈不上变异敏感）。
- **"一次生成"的边界**：从提示词提交，到 AI 第一次宣称"完成"为止。期间**允许** AI 自己驱动的内部循环（TDD 红绿、自查、工具调用），**不允许**任何人类的语义纠正。理由：harness 的两大目标之一就是提供自纠正反馈回路，把 AI 的自纠正算作"多轮试错"等于把 harness 一半的功效算成了成本。

## 4. 度量指标

### 4.1 一次过闸率（贯穿全书，零额外 token）

```
FPGY(task) = 首次生成连续通过的闸门数 / 5
```

三个副指标，从会话记录直接刮出：

- **RT**（返工轮次）：首次生成到五闸门全过，人类额外发起的语义纠正轮次数
- **RTC**（返工 token 占比）：`返工消耗 token / 总消耗 token`
- **EDD**（缺陷逃逸深度）：每个真实缺陷在第几道闸门被抓住。EDD 越小越"左移"

### 4.2 规格覆盖分数（第六章主结局指标）

```
SCS = (1×直接自动化覆盖 + 0.5×仅间接 + 0.25×仅手工e2e + 0×未覆盖) / 规格条目总数
```

第六章实验**只设这一个主指标**，其余全为次要指标（盲评 Critical/Important 条数、MS、总 token 消耗、RT）。理由：n 小时多主指标必然导致事后挑选。

### 4.3 变异指标（3.8 扩写 + 第六章）

```
MS   = 杀死变异数 / 有效变异数                    # 传统变异分数
SMS  = 能被测试区分的 spec 变异数 / spec 变异总数   # 规格变异分数（本书原创）
MPKT = 杀死的变异数 / 消耗的千 token              # 每千 token 杀死变异数
```

**MPKT 是本书的标志性指标**：它把"可信"和"token 预算"压进同一个数，是全书唯一问题的定量版本。

**SMS 的做法**：不变异代码，变异 spec 条款，然后问"现有测试套件能否区分这两份 spec"。区分不出，说明该条规格从未被真正验证过。已知可用样本（来自 ch03）：

| spec 变异体 | 原文 | 变异后 | 期望 |
| --- | --- | --- | --- |
| SM-1 | 声明列须保持**相对顺序** | 声明列须**相邻** | ≥1 个测试变红 |
| SM-2 | 在**任何记录暴露前**失败 | 在**首次迭代时**失败 | ≥1 个测试变红 |
| SM-3 | 精确名称匹配 | 大小写不敏感匹配 | ≥1 个测试变红 |

SM-3 在 3.7 节修复之前是**活的**（没有任何测试能区分它），修复之后才被杀死。这把 3.5 节"跳过 spec 评审的代价"从叙事变成了一个数字。

### 5.2 新 1.2 节的内容与写法

沿用全书骨架（提出问题 → 引导实操 → 分享体验）。

**开篇问题**：一段写得挺好的需求，交给 AI 一次生成，测试全绿了——这就算可信了吗？

**需求选型硬标准**（三条全部满足）：

1. 零 commons-csv 背景可懂——读者还没读 ch02
2. 至少含一个反直觉边界，否则 A 臂一次做对，本节没戏
3. 与 ch03/04/05 的三个需求不重叠，避免剧透

**选定需求**：解析时若某行字段数与表头数不一致，抛出带**行号**的异常。

其反直觉边界（这些正是 A 臂会默默替读者做主的地方）：

- 空行算不算一条记录？
- 文件末尾无换行的那一行算不算？
- quoted 字段内含换行时，"行号"指物理行还是逻辑记录号？
- 行号从 0 起还是从 1 起？含不含表头行？

**A 臂提示词**：必须符合 D2——一段写得相当不错的自然语言需求（含背景、规则、期望行为、要求补测试），但不含 EARS、决策表、验收标准，不调用任何 skill，不要求 TDD，不做 review。**提示词原文完整公开在书里**，让读者自行判断它是否是一个公平的对照。

**逐关解剖的呈现方式**：

| 闸门 | 本节怎么演示 | 读者看到什么 |
| --- | --- | --- |
| G1 | 跑 `mvn test`，报退出码 | 一个数 |
| G2 | 报 tests/failures/errors 与基线对比 | 全绿 |
| G3 | 把需求里的规则一条条列出，逐条问"哪个测试直接覆盖它" | **出现空行** |
| G4 | 挑一条 G3 通过的规则，把生产代码那一行注释掉，跑测试 | 测试**照样绿** |
| G5 | 读 diff，对照需求，找 AI 自作主张多做的事 | 多出的公开行为 |

节尾三件事，缺一不可：

1. 把五闸门表格正式交给读者，作为全书"可信"的操作定义
2. 明确写出"一次生成"的边界约定
3. **写明证据边界的欠条**：

> 这一节只证明了"一次生成会在第 N 道闸门破"，没有证明"用了本书的方法就不会破"。后者需要一个对照实验，本书在第六章 6.5 节完整给出：同一批需求、两臂、独立盲评，数据与提示词全部公开。

第 3 条是刻意设计——主动划定证据边界既提升可信度，又当场示范了全书要教的东西（证据 vs 主观判断）。

## 6. 第六章对照实验设计

### 6.1 两臂

- **A 臂**：按 D2 标准的自然语言需求，直接喂 Codex，一次生成
- **B 臂**：本书完整链路——拆需求 → EARS + 决策表 + 验收标准 → `test-driven-development` → 全量回归 → `requesting-code-review` → 故障注入

### 6.2 实验纪律（缺一条实验作废）

1. **物理隔离**：两臂各自一个 git worktree、各自一个全新会话。绝不在同一会话内跑。
2. **随机顺序**：先跑哪一臂随机决定，避免"第二次总是更懂需求"效应。
3. **盲评**：第三个从未参与生成的 Agent 会话；两份 diff 匿名化为"实现甲/实现乙"；评审提示词复用 3.7.1 那段（需求—证据矩阵 + 四档判定）。
4. **判分器标定**：先把一个已知含 Critical 的版本喂给盲评 Agent，抓不到则判分器不合格，换提示词重来。
5. **需求文本防泄漏**：法官拿到的需求必须是**原始需求**，不能是 B 臂产出的 EARS 规格。
6. **同日同模型**：两臂同一天、同一模型版本跑完，记录模型 ID。

### 6.3 样本形态（D4）

3 个需求 × 每臂重复 3 次。三个需求取自本书已有的三个场景（新功能 / 缺陷 / 技术债）。

此外，**ch01 那次单臂解剖作为第 4 个需求的 A 臂样本（n=1，无 B 臂）单独列出**，不参与方差计算，只用于在第六章回指开篇：开篇故事与结尾数据由此接上，全书成环，且 ch01 花掉的 token 被复用一次——正是 3.4.4「一次生成、六次使用」经济学在书结构层面的自我印证。**必须在表中显式标注它是 n=1 的补充样本，不是实验组成部分**，避免与 3×3 主数据混淆。

主报**同一任务下的变异系数**而非均值。理由：对 token 不自由的读者，"harness 降低方差 = 可预算"比"harness 提高均值"更有价值；且这绕开了"n 太小不能做统计"的尴尬。

### 6.4 变异测试落法

用 PIT 对 commons-csv 跑自动 mutation testing，**变异算子限定在新特性触及的类**（`CSVParser`、`CSVHeaderSchema`、`CSVFormat.Builder`），避免全库变异烧光 CPU。两臂跑同一批变异体。只用默认算子集，不自选，避免调参嫌疑。等价变异体人工剔除，剔除规则随数据公开。

## 7. 明确不做

- 不为读者提供一套"在自己项目上跑度量"的工具、脚本或 skill（D1：本体系是书内证据，不是交付物）
- 不在 ch01 放任何双臂对比、任何 B 臂产物、任何"我们的方法更好"的宣称
- 不引入 DORA 四/五指标作为本书指标——它们度量的是团队交付流，不是单次生成的可信度
- 不做统计显著性检验（n 不足），只报变异系数与一致性方向
- 不改动 ch02 结构
- 不把 ch01 的 A 臂需求做成 commons-csv 的真实 PR

## 8. 风险与效度威胁

| 风险 | 缓解 |
| --- | --- |
| **作者即实验者**：明知哪臂是 harness 臂，可能不自觉把 A 臂提示词写差 | A 臂提示词提前写死并在书中**原文公开**，让读者自行判断公平性。此条必须写进书，否则可信度归零 |
| **ch01 的 A 臂一次做对**，本节没戏 | 需求选型硬标准第 2 条（必含反直觉边界）；若仍做对，如实写出并换一个边界更多的需求，把"换需求"这件事也写进书 |
| **模型漂移** | 同日同模型跑完，记录模型 ID |
| **等价变异体**导致 MS 被系统性低估 | 人工剔除 + 公开剔除规则 |
| **MPKT 分母不稳**（受 prompt cache 影响） | 报区间而非点值，记录是否命中缓存 |
| **G3 是唯一 inferential 判据**，判分不稳 | 判分器标定（6.2 第 4 条）；ch01 的 G3 改为人工逐条列举，不用 Agent |
